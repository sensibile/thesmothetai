# taeguk-work-contract

Identify user situation, purpose hypothesis and expected effect. Record approved requirements/rule versions, scope, preservation conditions, target and limits. Separate unresolved meaning from ordinary implementation choices. Link each proposed check to an oracle. Produce a small work contract and next action, not a large mandatory template.

Read [evidence packet](references/evidence-packet.md) when exchanging results or resuming work. Apply within the user's existing scope and authority; this skill does not authorize external effects or criteria changes.

For a software change, carry the original request and approved requirements into the design handoff, include a draft verification plan and missing-tool construction scope during design, then give the verifier the exact design version for a verification plan prepared before implementation. The plan refines how requirements will be observed; it does not replace or weaken them. Keep unresolved meaning, thresholds, exceptions and authority questions for BOSS. A role definition does not authorize delegation.

완료 검토나 분석·제품 과업의 인계에는 [목적에 대한 완료 검토](references/completion-review.md)를 읽는다. 사용자 질문에 대한 답과 처리·계산 검증을 분리해 작업 계약에 연결한다. 승인된 완료 기준을 새로 만들거나 바꾸지 않는다.
